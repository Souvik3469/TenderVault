TenderVault — Deep Dive

Two documents, two vintages. The Docs/ folder at the repo root (SRS, SPMP, COCOMO, Gantt, DFDs, test-case workbook) is university coursework describing an earlier version of the system. It does not match the code. This document describes what is in the repository as of commit d840e18.

1. Overview

TenderVault is a multi-role B2B procurement platform. A company publishes a tender with a category, a minimum acceptable bid and a deadline. Vendors find it, ask clarifying questions and submit bids with a proposal message. The company awards exactly one bid; every other pending bid is rejected in the same database transaction. An admin reviews and rates tenders (1–5) and sees platform-wide stats.

The core design problem: a tender is a state machine with money attached, and awarding must not half-happen.

Deployment topology

  • Frontend: static Vite build on Vercel. VITE_API_URL sets the API base URL; default http://localhost:5000/v1.
  • Backend: one Node process (node build/server.js after tsc). Stateless, so it scales horizontally behind a load balancer. app.set('trust proxy', 1) assumes one proxy hop (needed so the rate limiter sees the client IP).
  • Database: MongoDB. prisma.$transaction on MongoDB requires a replica set; Atlas provides one.
  • Schema changes: npx prisma db push (MongoDB has no migration files). Indexes are created by db push.
  • Startup config is validated by Zod in src/v1/config/env.ts; the process exits if DATABASE_URL, USER_ACCESS_SECRET or the three Cloudinary variables are missing.

Flow A — company creates and publishes a tender

  1. Components/tender/CreateTender.jsx → optional uploadTenderImage(file) posts multipart to /tenders/upload; then createTender({... cost, deadline ISO ...}).
  2. api/client.ts → adds the Bearer token.
  3. routes/tender.routes.ts (POST /) → chain authMiddleware → validate(CreateTenderDto) → tc.createTender.
  4. middlewares/auth.middleware.ts → verifies JWT, sets req.user.
  5. dtos/tender.dto.ts → requires minimumBid or cost, normalises to minimumBid.
  6. controllers/tender.controller.ts → passes req.user.id / role / name and body to the service.
  7. services/tender.service.ts#createTender → role check, inserts a draft tender.
  8. middlewares/legacyFields.middleware.ts → adds cost to the response JSON.
  9. Later: Components/tender/TenderDetailsCard.jsx → usePublishTender → PATCH /tenders/:id/publish → tc.publishTender → publishTender → domain/tender-state.ts#assertTenderTransition(draft, open) → update.

Flow B — vendor submits a bid

  1. Components/bids/BidList.jsx → createbid(tenderId, { amount, message }).
  2. routes/tender.routes.ts (POST /:tenderId/bids) → authMiddleware → validate(CreateBidDto) → tc.createBid.
  3. services/tender.service.ts#createBid → role check; autoExpireTender (may close the tender); checks open, amount >= minimumBid, no existing bid; creates the bid.
  4. utils/notify.ts → un-awaited bid_received notification for the company.

Flow C — company accepts a bid (award)

  1. Components/bids/BidList.jsx → confirmation modal → acceptBid(bidId).
  2. routes/tender.routes.ts (PATCH /bids/:bidId/accept, declared before /:tenderId) → authMiddleware → tc.acceptBid.
  3. services/tender.service.ts#acceptBid → ownership, bid and tender transition checks; reads losing vendors; runs a three-write prisma.$transaction.
  4. utils/notify.ts → bid_accepted to the winner, bid_rejected to each loser, after commit.

Flow D — notification bell

  1. Components/notifications/NotificationBell.jsx → useUnreadCount (polls 30 s) and useNotifications.
  2. routes/notification.routes.ts → authMiddleware → getUnreadCount / getMyNotifications.
  3. services/notification.service.ts → count / findMany on Notification by userId (served by @@index([userId, read])).
  4. Click → useMarkRead → PATCH /notifications/:id/read → markRead checks notif.userId === userId.

5. LLD — function-wise flow

All functions below are in backend/src/v1/services/tender.service.ts unless another file is named.

Auth

  • authMiddleware(req, res, next) in middlewares/auth.middleware.ts → splits Authorization, runs jwtVerify(token, secret), reads payload.id, prisma.user.findUnique. Output: req.user. Errors: 401 JSON directly (does not go through errorMiddleware).
  • loginUser({ email, password }) in services/auth.service.ts → findUnique({ email }), bcrypt.compare. Signs { id } with HS256, expiry 7d. Returns { user (no password), accessToken }. Throws AppError('Invalid credentials.', 401) for unknown email or bad password (same message for both).
  • registerUser(input) in services/auth.service.ts → 409 if email exists; bcrypt.hash(password, 10); user.create. Returns user without password.

Tender lifecycle

  • createTender(userId, role, userName, input) → 403 unless role === 'company'. Writes a Tender with status: draft, companyName: userName, deadline parsed to Date, owner connected. Returns the tender.
  • publishTender(tenderId, userId) → findUnique; 404 if missing; 403 if companyId !== userId; assertTenderTransition(status, open); update to open.
  • closeTender(tenderId, userId) → same 404 / 403 order; assertTenderTransition(status, closed); reads pending bids' vendorIds; updates to closed; then notify(..., 'tender_closed') per pending vendor.
  • cancelTender(tenderId, userId) → same shape with target cancelled and tender_cancelled notifications. Bid statuses are not changed.
  • updateTender(tenderId, userId, input) → 404 / 403; 400 if awarded or cancelled; spreads input into update, converting deadline.
  • deleteTender(tenderId, userId) → 404 / 403; 400 if awarded; tender.delete (Prisma cascades to bids and questions, questions cascade to answers).
  • reviewTender(tenderId, role, evaluatorId, input) → 403 unless admin; 404; sets rating and evaluatorId; notify(companyId, ..., 'tender_reviewed').

Lazy expiry

  • autoExpireTender(tenderId) (private) → findUnique; returns null if missing. If status === open and now > deadline: update to closed, read pending bids, notify each vendor tender_closed, return the updated tender. Else return the tender unchanged. Called by getTenderById, createBid, getBidsForTender, askQuestion.
  • autoExpireAll() (private) → findMany({ status: open, deadline < now }) (uses @@index([status, deadline])); updateMany to closed; for each, read pending bids and notify. Called by getAllTenders only.

Queries

  • getAllTenders({ page, limit, category, status, role }) → autoExpireAll(); parseTenderStatus(status); null → empty page. Resolved status: parsed value, else open (the controller never passes role, so the admin branch is not reached from this route). Category is a case-insensitive equals. Runs findMany (skip/take, owner summary, _count.bids, newest first) and count in Promise.all.
  • searchTenders(name, page, limit) → title contains name (case-insensitive), status: open, paginated. Does not call autoExpireAll.
  • getMyTenders(userId, role) → 403 unless company; own tenders with bid counts.
  • getWonTenders(userId) → buyerId = userId AND status = awarded.
  • getTenderById(tenderId) → autoExpireTender; findUnique with owner and bid count; 404.
  • getTenderStats(tenderId, userId) → 404 / 403; reads all bid amounts and statuses; returns counts by status and min / max / avg of all amounts.
  • getAllCategories() → reads every tender's category, de-duplicates with Set.

Bids

  • createBid(tenderId, vendorId, role, input) → 403 unless vendor. Promise.all([autoExpireTender(tenderId), user.findUnique(vendorId)]). 404 if no tender; 400 if not open; 400 if amount < minimumBid; 409 if any bid by this vendor exists on this tender (findFirst). Creates bid pending with vendorName and companyId copied from the tender. notify(companyId, ..., 'bid_received').
  • getBidsForTender(tenderId, userId, role) → autoExpireTender; 404. Vendor → only own bid (or []). Company → 403 unless owner. Otherwise all bids with vendor (password stripped by safeVendor).
  • getBidById(tenderId, bidId, userId, role) → findFirst({ id, tenderId }); 404; vendor 403 unless own.
  • withdrawBid(bidId, userId) → 404; 403 unless vendorId === userId; assertBidTransition(status, withdrawn); update.
  • deleteBid(bidId, userId) → same checks as withdraw, then bid.delete.
  • rejectBid(bidId, userId) → loads bid with tender; 404; 403 unless tender owner; assertBidTransition(status, rejected); update; notify(vendorId, ..., 'bid_rejected').
  • acceptBid(bidId, userId) →
  • Step 1: bid.findUnique({ include: { tender: true } }); 404.
  • Step 2: 403 unless bid.tender.companyId === userId (ownership before state).
  • Step 3: assertBidTransition(bid.status, accepted) and assertTenderTransition(bid.tender.status, awarded) — tender must be open or closed.
  • Step 4: pre-capture othersToReject = pending bids on the tender except this one (vendorId only). Must run before step 5, which flips them to rejected.
  • Step 5: prisma.$transaction([bid.update → accepted, tender.update → awarded + buyerId, bid.updateMany pending others → rejected]). All-or-nothing.
  • Step 6: after commit, notify winner bid_accepted and each captured loser bid_rejected.
  • Returns { acceptedBid, updatedTender }.

Q&A

  • askQuestion(tenderId, userId, role, input) → 403 unless vendor; autoExpireTender; 404; 400 unless open; creates Question including asker summary; notify(companyId, ..., 'question_asked').
  • getQuestions(tenderId) → 404; questions newest first, each with asker and answers (oldest first) with owner role.
  • answerQuestion(tenderId, questionId, userId, role, input) → 403 unless company or admin; question.findFirst({ id, tenderId }) (prevents answering a question via another tender's URL); 404; company must own the tender (403); creates Answer; notify(question.userId, ..., 'question_answered').

Notifications and admin

  • getMyNotifications(userId), getUnreadCount(userId) in services/notification.service.ts → findMany / count by userId (and read: false).
  • markRead(notifId, userId) → 404; 403 unless owner; update read: true.
  • markAllRead(userId) → updateMany({ userId, read: false }).
  • getStats(role) in services/admin.service.ts → 403 unless admin; ten count queries in Promise.all.
  • getAllTendersAdmin(role, page, limit, status?, category?) → 403 unless admin; parseTenderStatus; category contains (case-insensitive); paginated with owner email.

Response path

  • legacyFields(req, res, next) → replaces res.json with a wrapper that runs mirror(body) first.
  • errorMiddleware(err, req, res, next) → AppError → its status; ZodError → 400; {status} → that status; else logs and returns 500.

8. Tradeoffs

DecisionGainCost
MongoDB + PrismaTyped client, enums, emulated relations, quick schema changes via db pushReferential actions run in the ORM, not the DB; transactions need a replica set; no migration history.
Lazy expiry instead of a schedulerNo extra process or cron infrastructureExpiry depends on read traffic.
Fire-and-forget notificationsRequest latency and success never depend on the notification writeDelivery is best-effort.
Polling (30 s) instead of WebSocketStateless API, trivial horizontal scalingUp to 30 s latency on the badge; constant background requests.
Role checks inside services, not route middlewareRole and ownership checks live next to the business ruleA new route must remember to call a service that checks.
legacyFields shimField rename shipped without breaking the deployed frontendEvery JSON response is walked recursively; remove once no client reads cost.

9. Summary

The logic layer is the strong part: strict layering, thin controllers, centralised errors, named lifecycle operations that check ownership before state, and an award path that is atomic, pre-captures losing vendors, and notifies only after commit. The schema was the weak part and was hardened in 8e77025 (enums, indexes, safe cascades, a declared state machine) without breaking the deployed client.
